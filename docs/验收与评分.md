# 验收与评分

总分 100 分。验收以个人提交、现场运行和答辩为准；仅能编译或仅能播放预录结果不能替代对应功能验收。

| 项目 | 分值 | 验收重点 |
| --- | ---: | --- |
| 环境配置与工程 | 10 | 干净目录构建、依赖说明、项目组织、资源释放 |
| 串口与双线程 | 10 | 64 字节结构不变、收发正确、共享数据安全、正常退出 |
| 相机取流与标定 | 15 | 稳定取流、异常处理、内外参标定、配置校验与误差说明 |
| 装甲板识别 | 25 | 角点质量、大小分类、数字分类、目标丢失处理、现场稳定性 |
| 位姿解算 | 15 | 大小装甲板 PnP、坐标变换、角度/距离、异常观测拒绝 |
| EKF 跟踪与预测 | 20 | 旋转车体模型、关联与切换、收敛、遮挡恢复、预测输出 |
| Web Debug 与答辩 | 5 | 关键数据可观测、问题定位能力、代码和算法解释 |

## 必验场景

1. 从空构建目录完成 CMake 配置与编译。
2. 连接串口后持续收发，验证帧头、帧尾、字段映射和 EKF 状态值。
3. 相机启动、连续取流，并演示超时或断流后的处理。
4. 静态大小装甲板识别、数字分类和 PnP 解算。
5. 目标平移、旋转和装甲板切换时的 EKF 跟踪。
6. 短时遮挡、目标消失及重新出现后的状态变化。
7. Web 页面持续显示关键曲线，页面刷新不影响视觉处理。
8. 正常退出程序，读线程、操作线程、串口、相机及 Web 服务均正确释放。

## 分档原则

- 完整：功能在现场场景中连续稳定运行，边界情况处理明确，学生能解释设计依据。
- 基本完成：主流程可运行，但稳定性、异常处理或结果质量存在明显不足。
- 未完成：仅有接口或离线片段，无法接入主流程，或无法独立解释实现。

## 安全与协议约束

出现以下任一情况时，相关功能项不得评为完整：

- 修改通信结构体字段、顺序、类型或 64 字节帧长；
- 把 `crc` 当作通信校验和而非 EKF 状态；
- 无目标、PnP 失败、EKF 未稳定或结果非法时仍允许开火；
- 使用未标定的占位参数完成验收；
- 依赖联网下载模型或资源才能现场运行；
- 两个线程之间存在可复现的数据竞争或无法正常退出。

## 加分边界

总分不超过 100。完成基础要求后，可在对应项目内认可更稳健的观测关联、更合理的噪声建模、可复现实验对比和清晰的性能分析；额外功能不能抵消基础功能缺失。
