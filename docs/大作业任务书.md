# 新赛季视觉组个人大作业任务书

## 1. 目标

在给定起始工程上完成一套装甲板自瞄流程：接收云台数据，采集图像，识别装甲板，解算目标位姿，通过 EKF 预测旋转车体状态，并将结果写回原 64 字节通信结构体。系统应能通过 Web Debug 观察关键中间量。

## 2. 已提供内容

- 串口类及其读写接口；
- 原 64 字节通信结构体；
- 双线程程序框架：读线程负责接收，操作线程负责取流、算法处理和发送；
- Web Debug 数值曲线模块；
- 弹道模型、卡尔曼滤波及规划相关参考代码；
- 最小可编译 CMake 配置。

参考代码不保证可直接用于最终方案。学生需要理解代码含义，只保留自己确实使用的部分。

## 3. 学生任务

### 3.1 环境与工程

- 自行安装编译器、CMake、OpenCV、Eigen、相机 SDK 和所选推理框架。
- 自行处理库路径、头文件路径和运行时动态库搜索路径。
- 在最小 CMake 的基础上添加自己的源文件及第三方依赖。
- 保证从干净的构建目录可以完成配置和编译，并在报告中写明复现步骤。

### 3.2 串口接入

- 不修改通信结构体的字段、类型、顺序和 64 字节总长度。
- `ReadFunction` 中只调用给定串口读取接口，验证完整帧后更新最新云台数据。
- `OperationFunction` 中将算法输出填入同一结构体，再调用给定串口写接口。
- 正确保护两个线程共享的数据，禁止同时读写同一对象造成数据竞争。
- `crc` 字段表示 EKF 状态，不是通信校验和，不实现 CRC 算法。

### 3.3 相机取流与标定

- 自行实现 `get_pic()`：完成设备枚举、相机打开、参数设置、开始取流、像素格式转换、超时处理和资源释放。
- 自行采集标定图片并计算相机内参、畸变系数及标定图像尺寸。
- 自行标定相机坐标系到云台坐标系的旋转和平移外参。
- 将结果填写到 `config/camera.yaml.example` 对应字段；示例文件中的值不可直接用于运行。
- 程序必须检查配置是否已标定、矩阵维度是否正确以及数值是否有限，缺失或非法时明确报错退出。
- PnP 与外参变换后的内部三维位置统一使用 m；根据装甲板毫米尺寸建模时必须显式完成单位换算。

### 3.4 装甲板识别

两种路线任选其一：

- 传统视觉：至少包含颜色/亮度处理、灯条提取、灯条匹配、装甲板角点生成和数字分类。
- 神经网络：模型需输出或可靠恢复装甲板角点、大小、编号与置信度；模型文件需随作业离线提交并注明来源。

无论选择哪条路线，后续模块使用统一结果：左上角开始顺时针排列的四个像素角点、大小装甲板类型、目标编号和置信度。识别不得假定每帧一定存在目标。

### 3.5 位姿解算

- 根据 [装甲板尺寸](../装甲板尺寸.txt) 分别建立大小装甲板三维点。
- 使用学生标定的内参、畸变参数进行 PnP 解算。
- 将相机坐标系结果转换至约定的云台/世界坐标系，并在报告中画出坐标轴方向。
- 计算距离、目标 yaw/pitch 和重投影误差；对 PnP 失败、深度非法或误差异常的观测进行拒绝。

### 3.6 EKF 跟踪与预测

- 建立可描述旋转车体中心平移、车体 yaw、角速度、装甲板高度及旋转半径的状态。
- 完成初始化、预测、观测更新、角度归一化、装甲板切换、离群点拒绝、短时丢失外推和超时重置。
- 根据处理延迟与预测时间选择目标装甲板，输出预测位置、目标角度、角速度和开火许可。
- 通过 `GimbalState::prediction_bias_s` 使用电控下发的预测时间偏置，单位为 s。
- `crc=0` 表示无 EKF 目标，`crc=1` 表示预测稳定，`crc=2` 表示存在目标但预测尚不稳定。

### 3.7 Web Debug

使用给定 `WEB_LOG(key, value)` 接口记录关键数值。至少应能观察：

- 相机帧率与单帧处理耗时；
- 检测数量、目标编号和置信度；
- PnP 距离、yaw/pitch 和重投影误差；
- EKF 车体中心、速度、yaw、角速度、半径及状态。

Web Debug 仅用于数值观测，不要求图像传输或在线修改参数。

## 4. 处理线程基本流程

`OperationFunction` 在得到一帧 `pic` 后按以下顺序工作：

```text
复制最新云台数据
  -> get_pic
  -> 空帧检查
  -> armor_detect
  -> armor_solve
  -> ekf_predict
  -> 无观测时由 EKF 进行纯预测
  -> 输出合法性检查
  -> 填写通信结构体
  -> 串口 Write
  -> Web Debug 记录
```

`pic.empty()` 时框架采用安全回包策略；为保持参考主循环的结构，前几次连续空帧会用黑帧继续经过检测、PnP 和 EKF，最终仍强制输出无目标。无目标或 PnP 失败时应将空观测传给 `ekf_predict`，以支持短时纯预测；结果过期以及出现 NaN/Inf 时必须禁止开火并输出无目标状态。EKF 未稳定时允许继续跟踪，但必须禁止开火。

## 5. 建议接口职责

起始工程中的函数名和调用顺序固定，内部类型可在保持职责清晰的前提下完善：

```cpp
bool get_pic(cv::Mat& pic);

std::vector<ArmorDetection> armor_detect(
    const cv::Mat& pic, TeamColor enemy_color);

std::vector<ArmorPose> armor_solve(
    const std::vector<ArmorDetection>& detections,
    const CameraParameters& camera,
    const GimbalState& gimbal);

PredictionResult ekf_predict(
    const std::vector<ArmorPose>& observations,
    const GimbalState& gimbal,
    double timestamp_seconds);
```

- `get_pic` 只负责获得一帧有效的 BGR 图像；帧时间由调用位置记录。
- `armor_detect` 不做 PnP 或 EKF。
- `armor_solve` 不维护跨帧跟踪状态。
- `ekf_predict` 不直接访问相机或修改原图。
